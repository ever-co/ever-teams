`getEmbedProjects(token, tenantId)` reads `GET /embed/projects` with the tenant in the `Tenant-Id` header: the projects a token from the host's `getToken` may track time on (ever-co/ever-gauzy#12080). An API without that route answers an error that keeps its 404 or 403 status; a read with no answer, or an answer that is not a list, comes back as a message with no status. `Select` takes `emptyMessage`, what its list says when it has no item ("No item found" without it). With `getToken`, the timer's project picker lists those projects, and its list says while they are read, when there is none (also on an API without the route) and when they could not be read (any refusal but an older API's 404 or 403 `EMBED_SCOPE`, such as 403 `EMBED_TOKEN_REQUIRED`), in English and French. A failed read is made again with the next token; a list read stays through token renewals, and is no longer shown once the host signs the person out. A project remembered from an earlier entry that the list does not hold (an empty list too) is let go, and picking another project lets the remembered task and client go: the task and client pickers list nothing to change them, and the API refuses a start with a task of another project. `useEmployeeOrganization`, `useMyTasks` and `useOrganizationProjects` no longer send a read the token cannot make: they answer an empty list, so the client and task pickers stay empty with no red notice. Without `getToken` nothing changes.
